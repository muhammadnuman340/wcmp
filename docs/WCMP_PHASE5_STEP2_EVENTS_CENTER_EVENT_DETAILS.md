# WCMP Phase 5 Step 2: Premium UI/UX V2 - Events Center & Event Details

## 1. Objective
Upgrade the existing Events Center and Event Details experience to the WCMP Premium UI/UX V2 standard. The goal is to provide a rich, scalable, professional cybersecurity event-monitoring interface while completely preserving real data flows, Room DB access, and the established security engine.

## 2. Visual Direction
- **Premium Dark Navy Interface**: Deep blues and high-contrast surfaces based on Phase 5 Step 1.
- **Strong Event Hierarchy**: Clear visual distinction for severities (Critical, High, Medium, Low, Info).
- **Compact & Readable Cards**: Generous 16dp radiuses, large semantic icons, and concise metadata.
- **Full-Screen Details**: A premium event details modal spanning 95% of the screen height, mimicking a full-screen experience with rich evidence thumbnails and security state confirmation.

## 3. Events Center Changes
- Replaced the legacy `EventsHeader` with the unified `WcmpTopBar`.
- Transformed `EventCard` to the new V2 timeline aesthetic:
  - Added 48dp semantic icon containers with subtle colored backgrounds.
  - Placed severity pill badges natively inside the top-right corner.
  - Added unified evidence count and navigation indicator at the bottom right.
- Retained smooth `LazyColumn` scrolling and real data connectivity via `EventsViewModel`.

## 4. Search & Filters
- **Search**: Preserved the `OutlinedTextField` search with updated Premium color tokens (CyanAccent borders, TextWhitePrimary typography).
- **Filters**: Upgraded `EventFilterBar` to use horizontal chips mapping to actual application event types: `ALL`, `APP_ACCESS`, `CAMERA`, `AUDIO`, `LOCATION`, `WCMP`.

## 5. Event Details Sheet Changes
- Re-architected `EventDetailsSheet` from a basic debug list to a Premium Modal experience.
- **Hero Header**: Displays a massive semantic icon matching the event severity, alongside the event's raw timestamp and evidence summary.
- **Event Information**: Structured layout presenting actual application, session ID, trigger source, duration, and status utilizing robust `DetailRow` components.
- **Evidence Presentation**: Implemented premium `EvidencePreviewCard`s representing captured camera, audio, or location evidence dynamically based on actual event types and evidence counts.
- **Security Details**: Visually confirms protection mechanisms via a dedicated "Protection was active" validation card.

## 6. Real-Data Integration
- **Strict adherence to Phase 5 constraints**: No fake data generation, no dummy evidence files. The interface routes directly through the existing `SecurityEvent` models generated by `EventsViewModel.kt` fetching from the true `SecurityRepository`.
- Evidence counts reflect actual captured items.
- Session IDs and package metadata render only if valid entries exist in the Room database.
